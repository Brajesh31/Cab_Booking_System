# 🚨 Incident Response Runbook

1. Confirm incident and identify affected routes, users, and data classes.
2. Assign an incident lead and record timestamps in UTC.
3. Contain: restrict access, revoke credentials, disable risky routes, or roll back.
4. Preserve sanitized evidence in restricted storage.
5. Assess exposure of passwords, hashes, JWTs, licence details, locations, or payment records.
6. Rotate credentials and signing keys where relevant.
7. Restore service and verify authorization/data integrity.
8. Coordinate notifications through the responsible security/privacy owner.
9. Complete an incident report and remediation tasks.

Never post sensitive logs, tokens, driver licence data, or location history in public GitHub issues.
